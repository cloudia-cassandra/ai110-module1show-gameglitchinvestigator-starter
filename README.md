# 🎮 Game Glitch Investigator: The Impossible Guesser

## 🚨 The Situation

You asked an AI to build a simple "Number Guessing Game" using Streamlit.
It wrote the code, ran away, and now the game is unplayable. 

- You can't win.
- The hints lie to you.
- The secret number seems to have commitment issues.

### The game's purpose

A number guessing game built with Streamlit. The app picks a secret number inside a range set by
the chosen difficulty (Easy 1-20, Normal 1-100, Hard 1-200) and the player tries to find it within
a limited number of attempts (6, 8 and 5 respectively). After each guess the game says whether to
go higher or lower, and the score rewards winning in fewer attempts. A "Developer Debug Info"
panel exposes the secret, attempt count, score and guess history so the game can be tested without
guessing blindly.

The real purpose of the exercise is the debugging: the app was generated by an AI, shipped with
deliberate bugs, and had to be played, diagnosed, repaired and tested.

### Bugs found

Found by playing the game first, then reading the code to explain each symptom. The full
reproduction table, with inputs and expected vs. actual behavior, is in
[`reflection.md`](reflection.md).

**Logic**

1. **Hint messages were swapped.** The outcome `"Too High"` was paired with the message
   `"Go HIGHER!"`, so the game steered the player away from the answer.
2. **The secret changed type on alternating attempts.** On every even-numbered attempt the secret
   was cast with `str()`. Comparing `int > str` raises `TypeError`, which a `try/except TypeError`
   quietly caught and replaced with a *string* comparison — so `"12390921309213"` was judged lower
   than `"60"` because `"1" < "6"`. This is why hints contradicted each other between two guesses.
3. **"Hard" was easier than "Normal".** It returned a 1-50 range, narrower than Normal's 1-100.

**State**

4. **"New Game" did not reset the game.** It reset only `attempts` and `secret`, leaving `status`
   as `"lost"`, so the status guard hit `st.stop()` on every rerun and the game was permanently
   unplayable after one loss.
5. **"New Game" ignored the difficulty**, drawing from a hardcoded `randint(1, 100)` — on Easy it
   could pick a secret outside the 1-20 range shown to the player.
6. **The secret never regenerated when difficulty changed**, so the sidebar could promise
   "Range: 1 to 20" while the secret was still from an old 1-100 draw.
7. **`attempts` meant three different things** depending on which line read it — it started at `1`
   but reset to `0`, so the same game had two starting states.
8. **Invalid input burned an attempt**, because the counter incremented before the input was
   validated.
9. **Invalid input could break the stopping condition**, since the out-of-attempts check only ran
   in the valid-guess branch while the counter climbed on rejected input too.

**Input and display**

10. **No range validation** — any integer was legal, which is how a guess of `12390921309213` was
    accepted in a 1-100 game.
11. **Decimals were silently truncated** (`3.9` became `3`), scoring a number the player never
    typed, and `except Exception` swallowed every error as "That is not a number."
12. **The prompt hardcoded "between 1 and 100"** regardless of difficulty.
13. **Scoring rewarded wrong guesses** — "Too High" awarded **+5** on even attempts while
    "Too Low" always cost −5, and the score had no floor, so a losing round ended at **−40**.
14. **The running score was never shown** during play, only in the debug panel.
15. **`history` mixed types**, appending raw strings for rejected input and ints for valid guesses.
16. **The guess box was keyed to difficulty**, so switching difficulty silently wiped what the
    player had typed, and the box never cleared after a submit.
17. **"Attempts left" was always one guess stale**, because the status line rendered above the
    submit handler in the script.

### Fixes applied

- **Comparison logic.** Paired each outcome with the correct message and removed the
  `try/except TypeError`, which existed only to hide the `str()` cast. The secret is now always
  compared as an `int`, so the fallback can never be reached.
- **Round state.** "New Game" resets `status`, `score` and `history` as well as `attempts` and
  `secret`, and draws from the current difficulty's range. The active difficulty is tracked in
  `session_state` so changing it regenerates the secret and starts a clean round.
- **Attempt counting.** `attempts` now has a single meaning everywhere — "valid guesses made",
  starting at `0` — and is incremented only after input validates. That one change fixed the
  off-by-one display, the burned turn on a typo, and the broken stopping condition together.
- **Input handling.** `parse_guess()` takes `low`/`high` and rejects out-of-range guesses, rejects
  decimals instead of truncating them, strips whitespace, and catches `ValueError` specifically.
  Rejected input is no longer recorded in `history`.
- **Scoring.** Removed the branch that awarded points for a wrong guess, made the penalty
  symmetric, and floored the score at `0`.
- **Display.** The prompt interpolates the real range, the running score is visible during play,
  and the status line is reserved with `st.empty()` and redrawn after the guess is handled so the
  counter is never stale.
- **Widgets.** The guess box moved into `st.form(clear_on_submit=True)`, which keeps a stable key,
  clears itself after each guess and makes Enter submit.
- **Structure and tests.** The four logic functions moved out of `app.py` into
  [`logic_utils.py`](logic_utils.py) so they can be tested without running Streamlit.
  `check_guess()` returns the outcome only, with display strings in an `OUTCOME_MESSAGES` dict.
  Nine regression tests were added, one per row of the bug reproduction log.

Each fix is marked in the source with a `# FIX [n]` comment explaining what was wrong, plus a
`# COLLAB` note recording how the bug was found and verified.

## 📸 Demo Walkthrough

A sample game on **Normal** difficulty (range 1-100, 8 attempts). The secret for this
walkthrough is **57** — visible in the Developer Debug Info panel. Every message below is the
real output from the app, not a paraphrase.

1. **Start the app.** The status line reads
   `Guess a number between 1 and 100. Attempts left: 8 | Score: 0`.
   The range comes from the difficulty selected in the sidebar, so choosing Easy changes it to
   1 to 20 and starts a fresh round.

2. **Enter `abc` and submit.** The game rejects it with **"That is not a number."**
   Attempts left stays at **8** — invalid input does not cost a turn.

3. **Enter `150` and submit.** The game rejects it with
   **"Guess must be between 1 and 100."** Attempts left is still **8**. Out-of-range guesses are
   refused instead of being scored.

4. **Guess `40`.** The hint reads **"📈 Go HIGHER!"** because 40 is below the secret.
   Attempts left drops to **7**.

5. **Guess `70`.** The hint reads **"📉 Go LOWER!"** because 70 is above the secret.
   Attempts left drops to **6**. The two hints point toward each other, narrowing the range to
   41-69.

6. **Guess `60`.** Still **"📉 Go LOWER!"** — closer, but high. Attempts left drops to **5**.

7. **Guess `57`.** The hint reads **"🎉 Correct!"**, balloons animate, and the game shows
   **"You won! The secret was 57. Final score: 70"**. The score is 70 because winning on the
   4th valid attempt scores `100 - 10 × (4 - 1)`.

8. **The round is over.** The guess box disappears and the app shows
   *"You already won. Start a new game to play again."* No further guesses are accepted.

9. **Click "New Game 🔁".** Attempts, score, history and status all reset, and a new secret is
   drawn from the current difficulty's range. The board is immediately playable again — this is
   the bug that originally made the game unusable after a single round.

**Losing a round:** submit 8 valid wrong guesses and the game ends with
*"Out of attempts! The secret was N. Score: 0"*, then stops accepting input until New Game is
clicked.

### Challenge 1: Advanced Edge-Case Testing

Three edge cases were chosen because each is a *different* way for input to look valid and still
be wrong:

| Edge case | Why it can break the game | Covered by |
|-----------|---------------------------|------------|
| **Negative numbers** | They parse as perfectly good ints, so the range check is the only thing keeping them off the board. `-0` also has to be caught like `0`. | `test_negative_guesses_are_rejected`, `test_negative_zero_is_rejected_like_zero`, `test_check_guess_still_orders_negatives_correctly` |
| **Decimals** | `int(float("3.9"))` is `3` — the original code scored the player on a number they never typed. | `test_decimals_are_rejected_never_truncated`, `test_decimal_is_not_silently_rounded_to_a_valid_guess` |
| **Extremely large values** | The original string comparison judged `12390921309213` as *lower* than `60`, and nothing capped a guess's magnitude. Python ints are unbounded, so `10**1000` must not overflow or hang. | `test_oversized_guesses_are_rejected`, `test_huge_values_compare_numerically_not_as_text`, `test_huge_values_do_not_raise` |

Probing those three turned up **three more problems that were still live**, now fixed and covered:

| Found while probing | Problem | Fix |
|---------------------|---------|-----|
| `"5_0"`, `"１０"`, `"١٠"` | `int()` accepts PEP 515 underscores and non-ASCII decimal digits, so `"5_0"` was accepted as **50** and full-width `"１０"` as **10** — numbers the player never typed. | `parse_guess()` now matches against `^[+-]?[0-9]+$` before converting. Ordinary formatting (`"+50"`, `"00050"`, `" 50 "`) still works. |
| `parse_guess(50)` | A non-string argument raised `AttributeError: 'int' object has no attribute 'strip'` instead of returning the `(ok, value, error)` contract. | Non-string input is coerced with `str()` first. |
| `update_score(0, "Win", 0)` | Returned **110**, above the intended 100 maximum — only the lower bound was clamped. | The win bonus is now clamped at both ends. |

### Challenge 4: Enhanced Game UI

Five enhancements, all additive. `check_guess()`, `parse_guess()` and `update_score()` were
**not modified**, so the core game logic is untouched and every pre-existing test still passes.
The new presentation logic was added as *pure functions* in
[`logic_utils.py`](logic_utils.py) rather than inline in `app.py`, which is what makes it
testable — see [`tests/test_ui_helpers.py`](tests/test_ui_helpers.py).

#### 1. Color-coded hints

| | Before | After |
|-|--------|-------|
| Too High | amber `st.warning("📉 Go LOWER!")` | **red** `### :red[📉 Go LOWER!]` |
| Too Low | amber `st.warning("📈 Go HIGHER!")` | **blue** `### :blue[📈 Go HIGHER!]` |
| Win | amber `st.warning("🎉 Correct!")` | **green** `### :green[🎉 Correct!]` |

Every outcome used to render as the same amber box, so "too high" and "too low" were visually
identical and direction had to be read word by word. Direction now has its own color.

- **New:** `OUTCOME_COLORS` dict in `logic_utils.py` — maps each outcome to a Streamlit color name.
- **Modified:** the hint block in the `if submit:` handler in `app.py` (marked `# UI [4]`), which
  now emits `:color[...]` markdown instead of `st.warning()`.

#### 2. Hot/Cold proximity badge

Each hint is followed by a temperature badge showing how close the guess landed:

`🎯 Exact` → `🔥 Blazing` → `🌶️ Hot` → `☀️ Warm` → `🌤️ Lukewarm` → `❄️ Cold` → `🧊 Freezing`

Distance is scaled to the size of the difficulty's range, so "hot" means the same thing on Easy
(1–20) as on Hard (1–200) instead of being 5 units either way.

- **New:** `get_proximity(guess, secret, low, high)` in `logic_utils.py`, with the thresholds in a
  `PROXIMITY_BANDS` list. Returns a label string.
- **Tested by:** `test_closer_guesses_are_never_colder` (walks every guess from 1 to the secret and
  asserts the label never moves backwards), `test_banding_scales_with_the_difficulty_range`,
  `test_degenerate_range_does_not_divide_by_zero`.

A real game now reads: `❄️ Cold` → `🌤️ Lukewarm` → `🌶️ Hot` → `🎯 Exact`.

#### 3. Session summary table

A live table of the round, replacing the raw Python list that was only visible in the debug panel:

| # | Guess | Result | Proximity | Score |
|---|-------|--------|-----------|-------|
| 1 | 20 | 📈 Go HIGHER! | ❄️ Cold | 0 |
| 2 | 75 | 📉 Go LOWER! | 🌤️ Lukewarm | 0 |
| 3 | 60 | 📉 Go LOWER! | 🌶️ Hot | 0 |
| 4 | 57 | 🎉 Correct! | 🎯 Exact | 70 |

Below it, a caption summarises the round: `Guesses: 4 | Closest: 57 | Range tried: 20 – 75`.
The table also stays on screen after a win or loss, so the finished board can be reviewed instead
of going blank.

- **New:** `build_session_table(log)` in `logic_utils.py` — converts the round log into
  display-ready rows, rendering each outcome as its player-facing message rather than its internal
  key.
- **New:** `render_session_table()` in `app.py` (marked `# UI [3]`), called both at the bottom of
  the script and on the game-over screen.
- **New:** `st.session_state.log`, a list of per-guess dicts. This is **additive** —
  `st.session_state.history` keeps its original shape (a list of ints), so nothing that reads it
  changes behaviour. It is reset everywhere the round resets.

#### 4. Metrics row

The one-line `st.info()` status became three `st.metric()` tiles — **🎯 Range**, **🎲 Attempts
left** (with a delta showing attempts used), and **⭐ Score** — so the numbers are scannable
instead of buried in a sentence.

- **Modified:** `render_status()` in `app.py` (marked `# UI [1]`), which now draws into its
  `st.empty()` placeholder with `status_box.container()`.

#### 5. Attempts progress bar

An `st.progress()` bar drains as attempts are used, and at two or fewer remaining a red caption
appears: `⚠️ Only 2 attempt(s) left!`

- **Modified:** `render_status()` in `app.py`, same block as above.

#### Verification

a full losing round (table persists on the game-over screen), a New Game reset (log cleared, table
gone), and the low-attempts warning firing at 2 remaining. No exceptions on any path, and all
79 tests pass.
